# Release evidence

1. Read `AGENTS.md`, the release README, and the target `CG-*` story.
2. Keep one user-visible outcome or tightly related hardening boundary per story.
3. Write binary, verifiable acceptance criteria.
4. Mark criteria complete only after repository evidence exists.
5. Record exact commands, passing counts, manual cases, and known limitations.
6. Distinguish code review findings from implemented changes.
7. Keep planned work out of implemented release claims.
8. Update README, docs index, release index, and changelog when the release surface changes.
9. Do not claim an npm publication, Git tag, deployment, test suite, or CI result without evidence.
10. Preserve historical `CG-` identifiers during branding changes.
