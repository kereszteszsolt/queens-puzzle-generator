# CG-003: Technical and user documentation

## Status

Implemented

## User story

As a user or maintainer, I want linked documentation for the game, architecture, algorithm, development, testing, branding, privacy, and releases so that behavior and boundaries can be changed deliberately.

## Acceptance criteria

- [x] Add a documentation index and complete user guide.
- [x] Document routes, components, composables, utility boundaries, state contracts, and lifecycle.
- [x] Document queen placement, connected-region generation, solution counting, optimization, limits, and performance boundaries.
- [x] Add development and verification instructions that do not invent a missing test suite.
- [x] Add canonical branding and privacy/contact rules.
- [x] Include at least three relevant Mermaid diagrams across the documentation.
- [x] Link implemented and planned release evidence from the README and documentation index.

## Evidence

- `docs/` contains the linked guides and release tree.
- Mermaid diagrams cover system context, component flow, lifecycle, generation, solver flow, documentation map, branding, and privacy data flow.
